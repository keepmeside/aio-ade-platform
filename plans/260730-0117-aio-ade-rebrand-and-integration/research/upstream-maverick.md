# Maverick (Justmalhar/maverick)

- **URL**: https://github.com/Justmalhar/maverick — homepage https://getmaverick.sh
- **One-liner**: "The OS layer above every AI coding CLI — run multiple agents in parallel, each in its own git worktree." A native, keyboard-first desktop ADE (agentic development environment) that spawns AI coding CLIs as real PTY subprocesses in isolated worktrees.

## Architecture

Three hard layers with an explicit rule that React never talks to the sidecar directly.

1. **React 19 webview** (`src/`) — workbench shell only: split tree, terminals, panels, editor groups. Canonical VSCode terminology enforced as a project constraint (`AuxiliaryBar`, `EditorGroup`, `Panel`, `ActivityBar`). Key discipline: `TerminalView` must obtain xterm instances via `TerminalRegistry.get()` and is forbidden from importing xterm.js directly; editor groups are hidden with `display:none` rather than unmounted (this is what buys the claimed sub-10ms workspace switching), with LRU suspension past 20 workspaces.
2. **Rust Tauri core** (`src-tauri/src/`) — intentionally thin: window/menu management, PTY manager, JSON-RPC pass-through to the sidecar, event forwarding. `src-tauri/src/main.rs`, `lib.rs`, `state.rs`, `menu.rs`, `pty_sink_tauri.rs`, `backend_detector.rs`, `bootstrap.rs`, plus 30 command modules under `src-tauri/src/commands/` (`agent.rs`, `pty.rs`, `git.rs`, `diff.rs`, `kanban.rs`, `mcp.rs`, `usage.rs`, `checks.rs`, `hooks.rs`, `pr.rs`, `preset.rs`, `providers.rs`, `remote.rs`, `skills.rs`, `workspace.rs`, `project_settings.rs`, `instructions.rs`, `context.rs`, `caffeinate.rs`, `browser.rs`, `attachment.rs`, `messages.rs`, `file_tree.rs`, `notify.rs`, `shell.rs`, `config.rs`, `project.rs`, `bootstrap.rs`). There is also a separate `src-tauri/core/src/**` crate.
3. **Bun sidecar** (`sidecar/`) — owns everything: `ProcessManager`, `WorktreeManager`, `SQLiteStore`, `ConfigLoader`, `SkillsEngine`, `MCPManager`, and it is what actually spawns the CLI subprocesses. Entry points `sidecar/main.ts` + `sidecar/index.ts`, RPC surface in `sidecar/rpc-handlers.ts`.

**Cross-layer types are mirrored by hand** between `src/lib/ipc.ts` and `sidecar/types.ts`. That's a documented smell they accepted.

**Agent provider abstraction** — this is the part most relevant to aio-ade's 34→2 agent strip:
- `sidecar/agent/provider.ts` — the interface.
- `sidecar/agent/providers/claude.ts` (+ `claude.test.ts`) — the reference adapter. It parses Claude Code's **NDJSON stream-json output**; there is a captured golden fixture at `sidecar/agent/providers/__fixtures__/claude-stream-hello.ndjson`.
- `sidecar/agent/session-manager.ts`, `sidecar/agent/checkpoints.ts`, `sidecar/agent/claude-session-file.ts` — session lifecycle, rewind checkpoints, and direct reading/manipulation of Claude Code's on-disk session JSONL.
- `sidecar/providers/catalog.ts` + root `providers.json` — a declarative provider/model catalog (a July 2026 addition, see `docs/superpowers/specs/2026-07-10-provider-model-catalog-design.md`).
- Backends named in config: `claude-code`, `codex`, `gemini`, `aider`, `ollama`, `custom`. Note `sidecar/ollama-models.ts` for local model enumeration.
- `sidecar/agent-oneshot.ts` — headless single-shot agent invocation, used for AI features (commit messages, PR text, review) rather than interactive chat.

**Data formats / storage**:
- Local SQLite at `~/Library/Application Support/maverick/` (macOS path in README — Windows path unverified) via `sidecar/sqlite-store.ts` with forward-only migrations `sidecar/migrations/001_initial.sql` → `006_agent_mode.sql` (002 kanban+presets+repo, 003 indexes, 004 kanban composer, 005 workspace title, 006 agent mode).
- Per-repo config: `maverick.json` (scripts, workspace path, base branch, preview URL), `maverick.yaml` (backends, skills, MCP servers, presets), `MAVERICK.md` (instructions). Global `~/.maverick/` holds `settings.json`, `MAVERICK.md`, `themes/`, `presets.yaml`. Loader: `sidecar/config-loader.ts`, `sidecar/project-settings.ts` / `project-settings-store.ts`.
- Instruction resolution chain: `MAVERICK.md` → `CLAUDE.md` → `AGENTS.md`, plus global `~/.maverick/MAVERICK.md`, prepended to the *first* prompt only. `sidecar/instructions-resolver.ts`.

**Hook-driven eventing** — `sidecar/hook-server.ts`, `sidecar/hook-events.ts`, `sidecar/claude-hooks.ts`. Maverick installs Claude Code hooks that call back into a local HTTP server, and uses those events to drive notifications and status instead of scraping terminal output. Spec: `docs/superpowers/specs/2026-07-02-hook-driven-notifications-design.md`. **This is the single most interesting delta vs. Orca's OSC-escape-code status detection.**

**Spec-driven dev process** — `docs/superpowers/specs/*` (design docs) paired with `docs/superpowers/plans/*` (execution plans), dated filenames, 47 files. Root also carries `PRD.md`, `MASTER-PLAN.md`, `SYSTEM-DESIGN.md`, `AGENTS.md`, `CLAUDE.md`, `HEALTH_REPORT.md`, `BUGHUNT_REPORT.md`, `todo.md`. Notably `docs/superpowers/specs/2026-06-23-conductor-for-windows-design.md` and `2026-06-23-windows-terminal-profiles-design.md` — they explicitly designed for Windows.

## Reusable pointers

Portability caveat first: **`sidecar/**` is Bun-runtime TypeScript** (`bun:sqlite`, `Bun.spawn`, `bun:test`). It is *closer* to portable than the Rust or the Tauri-bound React, but it is not drop-in for Electron's Node main process. Everything below is "read it and port the logic", not "copy the file".

- `sidecar/claude-hooks.ts` + `sidecar/hook-server.ts` + `sidecar/hook-events.ts` — **the highest-value read in the repo.** Shows exactly how to install Claude Code hooks into a managed config dir and receive typed lifecycle events over local HTTP. Orca already owns `CLAUDE_CONFIG_DIR`, so this slots in.
- `sidecar/agent/provider.ts` + `sidecar/agent/providers/claude.ts` + `sidecar/providers/catalog.ts` + root `providers.json` — the provider abstraction to model the post-strip Claude/Codex layer on. Note the split: *behaviour* in `provider.ts`, *metadata* in `providers.json`.
- `sidecar/agent/providers/__fixtures__/claude-stream-hello.ndjson` — a real captured Claude stream-json transcript. Useful as test data even if you write your own parser.
- `sidecar/agent/checkpoints.ts` + `sidecar/agent/claude-session-file.ts` — the rewind mechanism: git-state restore paired with session-JSONL forking. Read together with `session-manager.ts`.
- `sidecar/checks-module.ts` — post-agent automated triage of a worktree. Pairs with the `2026-06-25-checks-and-archive-design.md` spec.
- `sidecar/attachment-materializer.ts` + `sidecar/attachment-store.ts` — the large-paste→file→path trick.
- `sidecar/skills-engine.ts` — ~one file of YAML template interpolation; the cheapest win in the table.
- `sidecar/migrations/001_initial.sql` … `006_agent_mode.sql` — a compact, readable schema for workspaces/tasks/sessions/messages/usage. Worth reading even if aio-ade's storage differs; `006_agent_mode.sql` in particular shows the chat message model.
- `sidecar/branch-name-generator.ts`, `sidecar/pr-text-generator.ts`, `sidecar/commit-message.ts` — all three are thin wrappers over `sidecar/agent-oneshot.ts`. **`agent-oneshot.ts` is the real pattern**: one headless-agent invocation path that every AI-assist feature reuses. Orca has a commit-message generator; generalizing it the same way is the move.
- `docs/superpowers/specs/2026-06-23-conductor-for-windows-design.md` and `2026-06-23-windows-terminal-profiles-design.md` — **read these before doing anything Windows-related.** A peer project's written-down Windows pain (shell profiles, path handling, PTY) on the exact platform this dev machine runs.
- `docs/superpowers/specs/2026-06-10-worktree-flow-and-scm-design.md` — their worktree lifecycle design, to diff against Orca's existing implementation.
- `docs/superpowers/specs/2026-06-14-terminal-first-design.md` — the terminal-first architecture that Agent Mode was later layered onto, i.e. the migration path aio-ade would follow.

## Integration risks

- **License is the blocking risk.** No `LICENSE` file at root; GitHub API reports `license: null`; `package.json` is `"private": true` with no `license` field. Only a README line claims MIT. Under default copyright, absent a license grant, **no vendoring is permissible.** A README mention is weak evidence and would not survive a legal review or an OSS-compliance scan in a commercial product. Action: open an issue asking the author to commit a `LICENSE` file, and until then treat this repo as **read-for-inspiration only**. Do not copy code, do not copy substantial verbatim text from the specs.
- **Runtime mismatch — Bun vs Node.** The sidecar uses `bun:sqlite`, `Bun.spawn`, and `bun:test`. aio-ade is Electron/Node with pnpm. Every sidecar module needs its Bun APIs swapped (`better-sqlite3`/`node:sqlite`, `child_process`/`node-pty`, `vitest`). The README explicitly discourages npm/yarn/pnpm — so there is no supported Node path.
- **Framework mismatch — Tauri vs Electron.** All 36 `src-tauri/src/**.rs` files and every `@tauri-apps/*` call site (`invoke`, event listeners, dialog/notification/shell/updater/process plugins) are dead weight. The React layer is coupled to Tauri IPC, so `src/**` components can't be lifted without rewriting their data access. Realistically only `sidecar/**` logic and the docs are minable.
- **Windows.** Maverick's own README documents a macOS storage path (`~/Library/Application Support/maverick/`) and uses `caffeinate` (macOS-only binary). They wrote *specs* for Windows (`conductor-for-windows`, `windows-terminal-profiles`) but the presence of a spec is not proof of a working implementation — this is a solo project with 0 stars and near-certainly no Windows user base. **Assume Windows support is aspirational.** Do not trust any Maverick code path as Windows-validated; the specs are useful as a list of problems, not solutions. (Upside: Electron's `powerSaveBlocker` and `app.getPath('userData')` solve the two concrete portability issues above cross-platform.)
- **Bundle size.** Maverick's dep list is heavy: `monaco-editor` + Shiki 4, `pdfjs-dist`, `xlsx`, `highlight.js`, `framer-motion`, `@lobehub/ui` (patched!), `vscode-material-icons`, plus five xterm addons. Tauri hides some of this behind the system webview; Electron does not — it all ships. Pull deps individually and deliberately; `diff2html` and `js-yaml` are cheap, `xlsx`/`pdfjs-dist`/`monaco` are not.
- **Patched dependency.** `@lobehub/ui@5.15.2` requires a patch under `patches/`. A patched transitive UI dep is a maintenance liability and a supply-chain smell; avoid adopting it.
- **Security — `getmaverick.sh` is a curl-pipe-bash installer.** Do not execute it. Read it if you want, but it downloads and runs remote code.
- **Security — hook server.** The hook-driven event bus means a **local HTTP listener** in the app. If aio-ade reimplements this: bind to `127.0.0.1` only, use an ephemeral port, and require a per-session shared secret in the callback. Otherwise any local process (or a malicious page in the embedded browser) can forge agent events. Maverick's threat model here is unverified.
- **Security — session-file rewriting.** The rewind feature mutates Claude Code's own session JSONL on disk. Doing that inside Orca's per-account managed `CLAUDE_CONFIG_DIR` risks corrupting user session state if the CLI's format changes. Any implementation needs backup-before-write and a format-version check.
- **Pre-release / bus factor.** v0.1.0, 0 stars, 1 contributor, `BUGHUNT_REPORT.md` and `HEALTH_REPORT.md` in the root suggest active self-triage of known problems. Nothing here is battle-tested. Treat every design as a hypothesis, not a proven pattern.
- **Hand-mirrored types.** `src/lib/ipc.ts` ↔ `sidecar/types.ts` are kept in sync manually. If you copy their layering, don't copy this — aio-ade's `src/shared` (1,045 files) already solves it properly.

## Verdict

**inspiration-only** — with a license-permitting upgrade path to selective reimplementation. The license situation makes vendoring legally unsafe (README claims MIT, no LICENSE file exists, API says null, package is `private`), and even if that were resolved, the Bun-sidecar + Tauri-Rust architecture means almost nothing is copy-pasteable into an Electron/Node/pnpm app. But this is emphatically not a thin wrapper: 258 commits, ~50 sidecar modules each with a colocated test, 6 SQL migrations, 100% coverage gates, and 47 dated design specs make it the most architecturally serious peer found so far. Four things justify the reading time: **Claude Code hooks as a typed event bus** (strictly better than Orca's OSC-code status scraping, and nearly free given Orca already owns `CLAUDE_CONFIG_DIR`), **per-message rewind combining worktree restore with session-transcript forking**, **a checks module for automated triage of N parallel agent branches**, and **a data-driven provider catalog** that is directly relevant to how aio-ade should structure its post-34→2-strip provider layer. The `docs/superpowers/specs/` folder — especially the two Windows design docs — is cheaper and higher-yield to mine than the source code. Recommended action: file an issue asking for a LICENSE file, read the specs now, reimplement items 1, 2, 8, 12, and 19 from scratch.
