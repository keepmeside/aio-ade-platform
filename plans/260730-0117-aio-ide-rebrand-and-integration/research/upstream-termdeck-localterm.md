# TermDeck (huytieu/termdeck-localterm) — fork of monotykamary/localterm

- **URL**: https://github.com/huytieu/termdeck-localterm (default branch: `termdeck`)
- **One-liner**: Browser-native terminal multiplexer + Markdown knowledge workspace ("the deck your agents work on") — a daemon serves persistent PTY sessions over WebSocket to any device on your tailnet, with a wiki/canvas/diff-review surface beside them.
- **Stack**: TypeScript ESM pnpm monorepo (`pnpm@11.6.0`, Node >=24), Turbo, Vite (Vite Plus / `vp`), React + shadcn/ui + Tailwind, xterm.js, node-pty, tldraw (Canvas), Mermaid, Changesets. Root package is `@monotykamary/localterm-monorepo` v1.35.4.
- **License**: **MIT** (verified via GitHub API `license.spdx_id = MIT`; README states original localterm copyright retained, additions also MIT). **Vendorable into an MIT Electron app: YES** for the repo's own code. CAVEAT: the Canvas mode depends on **tldraw**, whose SDK license is *not* MIT (README explicitly says "tldraw's SDK license applies in production" and supports a hobby key via `localStorage.setItem("termdeck:tldrawLicense", ...)`). Do not vendor the canvas path without a tldraw license review.
- **Activity**: created 2026-07-13, last push **2026-07-24**, 903 commits on `termdeck`, **5 stars**, 1 fork, not archived, ~1.1 MB. Very young, very active, essentially a one-person fork. Upstream `monotykamary/localterm` is the real engineering mass; huytieu's additions are the wiki/canvas/tweak layers.

## Architecture

Monorepo, `apps/*` + `packages/*` (pnpm workspaces + Turbo).

**Packages (backend/CLI):**
- `packages/server` — the daemon. Owns PTY spawn, session registry, WebSocket transport, REST API, tailnet serve. GAP: internal file list not yet read.
- `packages/cli` — entry `packages/cli/bin/localterm.mjs`. Root scripts map `pnpm start` / `pnpm stop` / `pnpm cli` onto it. `pnpm cli status` prints the active URL.
- `packages/pi-extension` — GAP: purpose unverified.

**Apps (frontend):**
- `apps/terminal` — the whole React SPA. Entry `apps/terminal/src/main.tsx` → `app.tsx` → `components/shell.tsx`. It is a PWA: `public/manifest.webmanifest`, `scripts/generate-sw.mjs` + `scripts/sw-template.js` generate a service worker, `scripts/generate-icons.mjs` makes icons.
- `apps/harness/*` — standalone rendering harnesses (`alpha-mask`, `light-theme-rendering`, `donut.mjs`), each with its own `server.mjs` + `drive.mjs` + `index.html`. This is a **visual regression harness for terminal rendering driven over CDP** (`src/utils/connect-cdp.ts` exists on the app side). Notable pattern.
- `landing/`, `docs/`, `skills/localterm/`, `patches/`, `scripts/` (incl. `scripts/fix-node-pty.mjs` run at postinstall, and `scripts/lint.mjs`).

**Terminal runtime module boundary** (real files, `apps/terminal/src/lib/terminal-runtime/`):
- `create-terminal-session-lifecycle.ts`
- `create-terminal-surface.ts`
- `create-terminal-output-session.ts`
- `create-tab-output-activity.ts`
- `dispatch-terminal-control-message.ts`
- `constants.ts`

Plus `lib/terminal-scrollback.ts`, `lib/terminal-session-info.ts`, `lib/local-echo.ts`, `lib/terminal-themes.ts`, `lib/terminal-cursor.ts`, `lib/deck-session.ts`.

**Session data model** — `apps/terminal/src/lib/deck-session.ts` (read in full):
```ts
interface DeckSession {
  id; pid; shellName; cwd; title; createdAt; lastOutputAt; clients; state; pinned;
}
```
`clients` is a count ⇒ **multi-client attach is first-class**. `state` is one of `running` | `alive-quiet` | `ready`, mapped by `STATE_META` to a glyph + Tailwind color + label: amber pulsing ● "running", primary ● "Needs you" (alive-quiet), emerald ○ "Idle · done". Solid ● = live process, hollow ○ = idle.

**REST surface** (inferred from `deck-session.ts` and the `utils/fetch-*.ts` family — each fetcher is one file, one function):
- `GET /api/sessions` → session list (the grid's only data source)
- `GET /api/sessions/:id/pane?lines=N` → **last N rendered lines as plain text** ("the tile snapshot source")
- `POST /api/sessions` (cwd?) → spawn detached pinned session
- `DELETE /api/sessions/:id` → kill
- `POST /api/wiki/chat` → `{path, selection, prompt, sessionId?, line?, baseDir?}` → `{delivered: "session"|"new", id}`
- others implied by files: `fetch-git-diff`, `fetch-git-worktrees`, `fetch-ports`, `fetch-processes`, `fetch-secrets`, `fetch-themes`, `fetch-fonts`, `fetch-automations`, `fetch-agent-models`, `fetch-agent-skills`, `fetch-agent-session`, `fetch-agent-session-url`, `fetch-daemon-config`, `fetch-server-health`, `probe-server-health`.

**WS transport**: `utils/build-terminal-websocket-url.ts`, `utils/is-binary-message-data.ts`, `utils/decompress-frame.ts`, `utils/create-context-decompressor.ts`, `utils/detect-output-compress-mode.ts` ⇒ binary WebSocket frames with a **negotiated compression mode and a shared-context (streaming) decompressor** on the client. That is a real optimization, not a toy.

**Conventions** (`AGENTS.md`, read): pnpm only; interfaces over types; arrow functions except vendored `components/ui/**`; kebab-case filenames; **one utility per file in `utils/`**; magic numbers into `constants.ts` as `SCREAMING_SNAKE_CASE` with `_MS`/`_PX` suffixes; comments only when the "why" is non-obvious. Test tiers: deterministic unit (green gate), `@integration` (real PTY/WebSocket/child process), `@e2e` (real browser/HTTPS/OIDC). "A test that fails-then-passes is a bug."

## Integration risks

- **License**: repo itself MIT, safe to vendor with attribution (retain localterm's copyright + huytieu's). BUT `components/canvas.tsx` and `canvas/*` pull **tldraw**, whose SDK licence is not MIT and requires a key in production — exclude that path. Also verify transitive licences before copying any component wholesale (shadcn/ui is MIT; Mermaid MIT).
- **Architecture mismatch is the big one**: TermDeck is a *browser client + separate local daemon over HTTP/WebSocket*. Aio-IDE is Electron with in-process node-pty and IPC. Almost nothing transports 1:1 — the WS/compression/local-echo/multi-client layers are solving a problem Aio-IDE does not have locally. Value is in **models and UI**, not the transport.
- **Windows**: this is a heavy risk. Evidence of Unix assumptions — `shortenCwd()` in `deck-session.ts` special-cases `/Users/<name>`; the daemon serves `http://localterm.localhost:3417` and uses tailnet/loopback host tricks; `mise.toml`; `.mjs` shell-ish scripts; `pkill`-style cleanup in the repo's own conventions. Node >=24 and `pnpm@11.6.0` are also ahead of typical Electron toolchains. Assume any vendored daemon-side code needs Windows work; the renderer-side utils are the portable part.
- **React 19 / dependency skew**: TermDeck uses Vite Plus (`vp`) and `react-doctor`; Aio-IDE uses electron-vite + oxlint/oxfmt. Vendored components will need lint/format conversion and possibly React-version checks. GAP: exact React version unverified.
- **Bundle size**: pulling the wiki/WYSIWYG/Mermaid/tldraw surfaces would add megabytes to an Electron app for off-mission features. Restrict to the terminal/deck/diff/file-preview slices.
- **Security**: the daemon exposes a file-content HTTP endpoint (`build-file-content-url.ts`) plus a **same-origin proxy for remote deploy links** and GitHub fetches; there is an `auth-gate.tsx` and `@e2e` OIDC tests, so auth exists, but any path-serving endpoint copied into Aio-IDE needs strict root-jailing. The tweak-mode / `chatAboutSelection` flow **injects text into a live agent PTY** — that is a prompt-injection channel if any rendered content is attacker-controlled (e.g. fetched GitHub issue markdown). Treat rendered remote content as untrusted before wiring it to an agent.
- **Maturity**: 5 stars, one author, 17 days old at time of writing, 903 commits (mostly inherited). No community vetting. Read it as a design source, not a dependency.
- **Not an npm dependency**: root manifest is private and the workspace is not published as consumable libraries (`packages/cli` is a bin). There is nothing clean to `pnpm add`.

## Verdict

**inspiration-only, with two or three targeted vendor-code lifts.** It is not a dependency — the monorepo is private, its runtime is a browser-plus-daemon split that Aio-IDE's in-process Electron model does not need, and half the surface area (wiki, canvas, mobile keyboard, QR pairing) is off-mission or license-encumbered. What it does have is a *better product model for exactly Aio-IDE's problem*: the **session deck** (tile wall of all live agents fed by cheap text pane-snapshots rather than N mounted terminals), **detached sessions with a grace window and reattach**, and the **terminal-output `path:line` → rendered artifact drawer**. Those three are the report's actionable core, and the third is small enough to lift file-by-file. Second tier worth copying verbatim: the scroll-anchor/scrollback-purge utils, the keyboard-shortcut registry, and the terminal theme colour maths. Everything transport-shaped (compressed WS frames, local echo, multi-client fan-out) should be ignored unless Aio-IDE invests in its SSH/WSL remote-host path. Expect Windows work on anything daemon-side; the renderer utils are the portable half.
