## Architecture

Five source trees, three shells, one renderer. This is the single most transferable thing in the repo.

**Process/context layout** (from README's Architecture section, confirmed against the file tree):

| Tree | Role | Real files seen |
| --- | --- | --- |
| `src/main` | Electron main shell | `src/main/index.ts` (93 KB — the monolithic shell), `src/main/canvas-control-core.ts`, `src/main/notch-hud.ts`, `src/main/pairing-service.ts` |
| `src/preload` | The *only* bridge; exposes `window.nodeTerminal` | `src/preload/index.ts` (28 KB) |
| `src/renderer` | React UI, canvas, nodes | `src/renderer/canvas/Canvas.tsx` (**367 KB**), `src/renderer/nodes/*`, `src/renderer/state/*` |
| `src/shared` | Types + IPC channel names used by all three | `src/shared/types.ts` (90 KB), `src/shared/ipc.ts`, `src/shared/worktree.ts`, `src/shared/agents/normalize.ts` |
| `src/core` | **`CorePlatform` seam** — every service (PTY, workspace/settings, git, agents, hooks) lives here and *never imports `electron`* | `src/core/pty-manager.ts` (**120 KB**), `src/core/workspace-store.ts`, `src/core/git-service.ts`, `src/core/agent-status-mirror.ts` (70 KB), `src/core/agents/hook-server.ts`, `src/core/context-link.ts` |
| `src/server` | Second implementation of the seam: headless "Server Edition" serving the same renderer to a browser over WebSocket-RPC | `src/server/index.ts`, `src/server/backpressure.test.ts` |

Two abstractions carry the whole design:

1. **`CorePlatform`** — services are electron-free. Electron is *one* host; the browser Server Edition is another, booting the identical services and filling `window.nodeTerminal` from `src/renderer/bridge/ws-bridge.ts` (34 KB) instead of preload. One codebase → desktop app + self-hosted browser app + iOS companion.
2. **`TerminalTransport`** — the renderer depends only on this interface, never on IPC or `node-pty`. `LocalTransport` hits the local host; `RemoteTransport` speaks to an agent over SSH (`src/main/remote-ssh/ssh-project.ts`, 50 KB; `src/core/remote-ssh/control-master.ts` uses an SSH ControlMaster). Remote projects therefore drop in without the canvas UI knowing.

**Storage / data format**: a *project* is a canvas with its own working directory. React Flow's node array is the live source of truth; projects serialize their nodes to disk via `src/core/workspace-store.ts` (with `workspace-store.test.ts`, 40 KB of tests). Renderer state is zustand: `src/renderer/state/workspace.ts` (43 KB), `state/projects.ts`, `state/agentStatus.ts`, `state/presence.ts`, `state/worktrees.ts`.

**Session persistence protocol**: terminals are not plain PTYs — each is wrapped in a **tmux** session. `src/core/tmux-naming.ts`, `tmux-conf.test.ts`, `tmux-hint.ts`, plus `src/core/pty-coattach.test.ts` (64 KB) and `pty-single-user.test.ts` show the co-attach model: the app attaches/detaches from long-lived tmux sessions, so closing a node's window ≠ killing the process. Only the node's × truly ends a session. Scrollback and live processes survive a machine reboot; the marketing page claims 46 sessions restored including a reattached `claude --resume`.

**Agent status protocol** — the important architectural divergence from Aio-IDE. nodeterm does **not** scrape terminal output. It runs a loopback **hook server** (`src/core/agents/hook-server.ts`) and installs per-agent hook scripts (`src/core/agents/hooks/claude.ts`, `claude-tui.ts`, `codex.ts`, `codex-trust.ts`, `gemini.ts`, `opencode.ts`, orchestrated by `hooks/index.ts`, `hooks/install-helper.ts`, `hooks/managed-script.ts`). The agent CLI itself calls back into the app on lifecycle events, producing `RUNNING` / `NEEDS YOU` badges, subagent cards with live transcripts, and a context-window meter. `src/core/agents/pending-approvals.ts` + `docs/hook-reply-approvals.md` show permission prompts being answered *through the hook reply channel* rather than by typing into the TTY. The mirror that reconciles all this is `src/core/agent-status-mirror.ts` (70 KB code, 72 KB tests).

**Context Link protocol** (`src/core/context-link.ts`, `context-link-core.ts`, `context-link-render.ts`, plus `context-link.cli.test.ts` and `context-link.handler.test.ts`): a canvas **edge** is a context channel. See Features #2 for the mechanism.

**Collaboration/relay**: `src/core/presence/hub.ts`, `src/renderer/canvas/collab-sync.ts`, `src/core/canvas-sync.convergence.test.ts` (28 KB — convergence tests imply CRDT-ish merge), `src/main/remote/relay-host.ts` / `relay-socket.ts` / `relay-trust.ts` / `standing-host.ts`, `src/main/pairing-service.ts` (QR pairing), `src/core/push-notify.ts` (phone push with zero open ports — hook server stays loopback, push egresses over HTTPS under a grant the phone drops over SSH).

**Docs worth reading in-repo**: `docs/SERVER.md`, `docs/remote-sessions.md`, `docs/hook-reply-approvals.md`, `docs/ssh-agent-skills.md`, `docs/team-presence.md`, `docs/relay-quota.md`, and the design specs under `docs/superpowers/specs/`.

## The "nodes" concept, precisely

A **node is not** an SSH host and **not** a command in a dataflow graph. A node is a *placed, persistent piece of live workspace state*. The site's line is literal: "Everything is a node."

Verified node kinds, mapped to real files in `src/renderer/nodes/`:

| Node | File | What it actually is |
| --- | --- | --- |
| Terminal | `TerminalNode.tsx` (109 KB) | A real shell: xterm.js front-end over a tmux-wrapped PTY. Click-to-rename, colour, tags, AI-generated name. |
| Agent | (a Terminal preset) | Same PTY node, launched with an agent CLI command: Claude Code / Codex / Gemini / opencode / custom. Status comes from hooks, not scraping. |
| Chat | `ChatPanel.tsx` | **Not a PTY.** An SDK-driven Claude chat: streaming, in-chat permission prompts, image paste, cost meter. |
| Subagent | `SubagentNode.tsx` | Auto-spawned child card showing a live subagent transcript, token count, tool calls — fan-out is *rendered on the canvas*. |
| Loop | `LoopNode.tsx` | Repetition / scheduling driver (site mockup shows a cron node `0 9 * *` kicking off a `general-purpose` fan-out of three workers). |
| Sticky | `StickyNode.tsx` | Coloured free text. Can be *linked into* an agent as context. |
| Group | `GroupNode.tsx` | A frame that moves related nodes together. |
| Editor | `EditorNode.tsx` + `lazyMonacoNodes.tsx` | Monaco editor bound to a file; ⌘S saves; markdown/image preview. |
| Diff | `DiffNode.tsx` | Monaco diff editor over staged/unstaged git changes. |
| Browser | `BrowserNode.tsx`, `BrowserSurface.tsx`, `BrowserStartPage.tsx`, `browserUrl.ts` | A real browsing surface with a start page and URL parsing. |
| Web / Video | `WebNode.tsx`, `VideoNode.tsx` | Render a page or a video inline on the canvas. |
| Mascot / Dino | `AgentMascot.tsx`, `DinoNode.tsx`, `dino/*` | Cosmetic; `DinoNode` is a multiplayer easter-egg game with its own authority/sync model. |

**How nodes connect**: you draw edges yourself; there is no automatic graph execution. An edge means "these two may read each other," and reads are **pull-based** — see #2. So it is **not** a visual pipeline/dataflow engine over terminals. It is a **spatial workspace** (a map) with an opt-in context-sharing relation layered on top. The only execution-flow-ish element is the Loop/cron node.

**Canvas interaction model**: unbounded pan/zoom (React Flow), drag to place, group frames, project tabs each with their own canvas and cwd, ⌘K command palette, ⌘⇧E explorer, ⌘M markdown toggle, ⌘Z/⌘⇧Z undo-redo on the canvas graph, right-click action menus on empty space and on nodes, zoom readout, fullscreen, a usage meter. Tagline: "Think in space, not tabs." Stated design motivation: built for ADHD / scattered workflows — stacked tabs hide context, a map preserves the mental model.

## Integration risks

- **License is the decisive blocker.** BUSL-1.1 is not open source by its own text. Derivative works remain under BUSL, so vendoring any file would make Aio-IDE's MIT claim false and, at the moment Aio-IDE is distributed, put it in breach — Aio-IDE is a standalone desktop product that competes with the Licensed Work, exactly what the Additional Use Grant excludes. The Change Date (4 years from each version's publication, → MIT) means v0.2.30 does not become MIT until ~2030, per-version. **Do not copy code, do not copy distinctive comments or file structure verbatim.** Reading for ideas is fine and normal; keep the reimplementation independent and do not paste.
- **No Windows support, at all.** Build targets are macOS dmg/zip and Linux AppImage/deb only. Session persistence *depends on tmux*, which does not exist under ConPTY. The single most attractive feature (#6) has no Windows path, and Aio-IDE's dev machine is Windows 11. Any persistence work must be designed from scratch (detached helper process, or lean on `claude --resume` / Codex session resume + transcript replay). Verify early rather than discovering it late.
- **React version mismatch.** nodeterm is React **18**.3 with `@types/react` 18; Aio-IDE is React **19**. `@xyflow/react` 12 supports React 19, but any React-18-era patterns observed in nodeterm's node components (legacy ref handling, `useSyncExternalStore` shims) should not be mirrored.
- **Canvas performance is the real engineering risk.** `Canvas.tsx` is 367 KB and `TerminalNode.tsx` is 109 KB in a *single-author six-week-old* project — evidence that "many xterm.js instances on a transformed, zoomable surface" is genuinely hard. Each xterm WebGL renderer is a canvas context; browsers cap those (~16 live contexts) and CSS-transformed canvases blur or thrash. Expect to need: virtualization by viewport, a static bitmap/last-frame placeholder for off-screen or zoomed-out nodes (the repo even has a `stale-frame.png` at root, suggesting exactly this), and a hard cap on simultaneously-live renderers. Budget for this explicitly; it is where an XL estimate on #1 actually goes.
- **Bundle size.** Monaco (~5 MB min) plus xterm plus React Flow. nodeterm mitigates with `lazyMonacoNodes.tsx`. `smart-whisper` additionally pulls a native module *and* a model download — a second `electron-rebuild` target beyond `node-pty`, and native rebuilds on Windows are the usual source of pain. Skip it.
- **Security surface of the hook mechanism.** The hook server is a loopback HTTP listener that agent CLIs call into, and hook installation *writes executable scripts into the user's agent config directory*. In Aio-IDE that directory is the per-account managed auth dir, which also holds OAuth tokens. Any hook-script writer must not touch credential files, must bind loopback-only, must authenticate callers (a per-session nonce, not just "localhost"), and must survive a hostile repo checkout that ships its own `AGENTS.md`. Context Link's `AGENTS.md` appending is itself an injection vector: a malicious repo can pre-seed instructions, so the appended pointer must be clearly delimited and the app must not trust `AGENTS.md` content it reads back.
- **`private: true` and no CONTRIBUTING clarity.** The package is marked private and licensing is single-author. There is no upstream contribution path that would let Aio-IDE co-develop; treat it as a closed competitor that happens to publish its source.
- **Fast-moving pre-1.0 target.** Created 2026-06-15, at 0.2.30 six weeks later. Any observation in this report may be stale within weeks. Re-verify before acting on specifics.

---

## Verdict

**inspiration-only** — with one carve-out: install `@xyflow/react` (MIT) from npm and build the canvas yourself. BUSL-1.1 makes vendoring legally impossible for a distributed MIT Electron app, and Aio-IDE lands squarely inside the Additional Use Grant's competition exclusion, so not one line can be copied until each version's individual Change Date (~2030). That is fine, because the value here is conceptual, not code: nodeterm's real contribution is the demonstration that a spatial canvas beats tab stacks for supervising many concurrent coding agents, and that a canvas *edge* is the right affordance for pull-based context sharing between them. Those two ideas — plus the `CorePlatform` electron-free service seam that makes services unit-testable — are what a fork already stripping down to Claude Code + Codex should absorb. Ranked by value-per-effort, build in this order: **Context Link (#2, effort M, and Claude+Codex is exactly the supported pair)** → **canvas + group frames (#1, #10)** → **subagent fan-out and hook-reply approvals (#5, #4)**. Skip everything mobile, relay, multiplayer, Server Edition, notch, and Whisper; and read `codex-trust.ts` before Aio-IDE's first unattended Codex run in a fresh worktree, because that bug is coming.

## Gaps

- **Not read: actual source of `context-link.ts`, `Canvas.tsx`, `hook-server.ts`.** File paths, sizes, and the node-type inventory are verified from the repo tree via the GitHub API; the *mechanism* descriptions for Context Link and hook status come from the official docs (`nodeterm.dev/docs/agents/context-link`) and README, not from reading the implementations. Deliberate choice: BUSL means the code cannot be used anyway, and runway was limited. If a deeper Context Link spec is needed, `src/core/context-link-core.ts` and `context-link.handler.test.ts` are the two files to read.
- **The `#nodes` fragment specifically** — nodeterm.dev is a marketing SPA; I read the whole rendered page plus the docs overview and the Context Link doc page. `nodeterm.dev/docs/core-concepts/node-types` returned 404 on the guessed path, so the per-node-type reference page was not read; the node inventory in this report is reconstructed from `src/renderer/nodes/` filenames + README + the docs overview, which agree with each other.
- **`LoopNode` semantics are inferred.** File exists; cron behaviour comes from a marketing mockup (`0 9 * *`). Whether it is a true scheduler, a retry-until-pass loop, or both is unverified.
- **Star/fork counts are a 2026-07-30 snapshot** (121 / 22). Growth rate unknown — the repo is 6 weeks old, so this could be a spike or a plateau.
- **Runtime behaviour entirely unverified.** No build, no run — the app has no Windows target and this machine is Windows 11. Claims about 46 restored sessions, reattached `claude --resume`, badge latency, and canvas performance at scale are the vendor's, not measured.
- **Canvas performance at scale is the biggest unknown and the biggest risk to feature #1.** How many simultaneously-live xterm instances nodeterm actually sustains, and what its zoom-out degradation strategy is, is unmeasured. The root-level `stale-frame.png` hints at a last-frame-bitmap approach but that is a guess from a filename. **Recommend a throwaway spike before committing to #1**: 12 xterm.js WebGL instances inside `@xyflow/react` nodes on Windows, measure frame time while panning.
- **Whether Codex/Claude CLI versions Aio-IDE pins still expose the hook surfaces nodeterm relies on** — not checked. Hook APIs in both CLIs change frequently.
- **`@xyflow/react` is listed under `devDependencies`, not `dependencies`.** Almost certainly because Vite bundles the renderer so it need not ship at runtime, but the packaging implication was not verified.
